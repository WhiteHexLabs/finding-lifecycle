# Artifact contract — result.yaml → normalization → artifact-manifest.yaml

How declared outputs become immutable canonical evidence.

## Pipeline

```text
load result.yaml
  → validate status/note/schema
  → validate declared source paths
  → validate target was not modified (scope re-fingerprint)
  → copy artifacts into steps/<N>/attempts/<k>/artifacts/
  → hash all canonical artifacts
  → generate steps/<N>/artifact-manifest.yaml (COMPLETED attempts)
  → freeze attempt metadata in run.yaml
  → update run revision
```

References to external output paths are never retained as the source of
truth — canonical copies are.

## Canonical layout and retries

One layout, used consistently: every recorded attempt `k` owns
`steps/<N>/attempts/<k>/artifacts/`. Prior attempts are never overwritten
(history preservation). `steps/<N>/artifact-manifest.yaml` describes the
currently accepted COMPLETED attempt and points into its attempt directory
(paths relative to the step dir). `steps/<N>/result.yaml` is a convenience
copy of the latest declared result; the per-attempt archive under
`attempts/<k>/result.yaml` is authoritative.

## Copying rules

1. Never overwrite a previous attempt (separate attempt directories).
2. The primary report becomes `report.<ext>` (default `.md`); the log
   becomes `log.<ext>` (default `.log`); extra artifacts keep their
   basename slugified.
3. Filename collisions within one attempt resolve deterministically
   (`name`, `name-2`, `name-3`, …).
4. Files receive SHA-256.
5. Directories are copied recursively and receive a deterministic tree
   hash (below).
6. Symlinks are rejected as artifact sources (top-level and nested) —
   explicit policy, no silent following.
7. Path traversal is rejected (canonical paths must stay in the step dir).
8. Missing declared artifacts are rejected (record fails).
9. Artifacts inside the audited target tree are rejected — a report in the
   target means the skill wrote into the target, which stales the batch
   anyway.
10. Key/credential material is rejected: PEM private-key blocks,
    `private key =`/`api key =`-style assignments and mnemonic/seed-phrase
    markers. Bare 64-hex values (block/code/tx hashes — ubiquitous
    legitimate evidence) are deliberately not scanned here; the deep
    secrets scan with justified exceptions runs in finding-lifecycle's
    PACKAGED gate.

## Directory tree hashing

Deterministic digest, no filesystem mtimes:

1. recursively list regular files;
2. use normalized relative POSIX paths;
3. no transient junk is ignored (everything hashes);
4. sort by normalized relative path;
5. hash each file (SHA-256);
6. build the canonical record stream `<relative-path>\0<file-sha256>\n`;
7. SHA-256 the concatenated stream.

Stored as `tree_sha256` plus `file_count`.

## Supported artifact types

`report log findings poc trace coverage subagent-results analysis other`

Strict known types plus `other`; unknown types are rejected at record time.
Logic never assumes reports are Markdown.

## artifact-manifest.yaml (Orchestrator internal interface)

Generated by the orchestrator only — audit skills never author it:

```yaml
schema: whitehexlabs.audit-artifacts/v1
run_id: run-…
step: 3
attempt: 1
status: COMPLETED
skill:
  name: <name from the SKILL.md frontmatter, or dir basename>
  path: /path/to/SKILL.md
  sha256: …
target:
  fingerprint_sha256: <scope manifest digest>
artifacts:
  - id: primary-report
    type: report
    path: attempts/1/artifacts/report.md   # relative to the step dir
    sha256: …
  - id: poc
    type: poc
    path: attempts/1/artifacts/poc/
    tree_sha256: …
    file_count: 3
```

`check`/`finalize`/`handoff verification` re-validate every entry (path
confinement, file hash or tree hash + count, ≥1 report artifact, unique
ids, correct run/step/attempt binding).

## Legacy batches (pre-split compatibility)

Completed steps recorded by the old combined tool keep their frozen copies
as `steps/<N>/attempt-<k>-report|log…`. On `finalize` (and only then) a
compatibility adapter exposes them as canonical manifest entries generated
from the existing frozen copies. Missing artifacts are never fabricated:
the report must exist; the log is included only when it was frozen.
Unfinished legacy batches resume under the new CLI with the legacy result
shape still accepted; new recordings use the canonical layout.
