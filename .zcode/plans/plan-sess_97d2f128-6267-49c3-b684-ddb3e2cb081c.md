# 新增阶段:PRIOR_ART_CHECKED(官方审计报告去重)

## 设计要点

在 `DISCOVERED` 与 `CROSS_CHECKED` 之间插入新阶段 **`PRIOR_ART_CHECKED`**,流水线由七阶段变八阶段:

```
DISCOVERED → PRIOR_ART_CHECKED → CROSS_CHECKED → FORK_PROVEN → TRIAGED
           → PACKAGED → SELF_REVIEWED → SUBMITTED
```

发现漏洞后、投入复核/实证成本前,先完成:到项目方官方技术文档站或 bounty 平台项目页收集审计报告链接 → 下载报告到 `evidence/<id>/prior-art/` → 逐份用根因关键词(函数名、机制词)检索 → 记录每份报告的重合结论。与已发布审计重合通常意味着已知问题 → `close INELIGIBLE`(保留"漏洞存在但不符合资格"语义);仅当规则明确允许时才可继续。

**输入文档** `evidence/<id>/prior-art.yaml`(机器可查):

```yaml
discovery:                              # 去哪里找的(至少一条)
  - {kind: docs_site|program_page|other, url: ..., fetched_at: ..., note: ...}
reports:                                # 本地副本 + 哈希
  - {title: ..., url: ..., auditor: ..., date: ...,
     path: evidence/<id>/prior-art/<file>, sha256: <64hex>}
checks:                                 # 每份报告一条
  - {report: <title>, searched_for: [关键词], result: NO_MATCH|MATCH|PARTIAL|NOT_SEARCHABLE,
     detail: ..., location: "p.12 / §3.4",
     still_eligible: {rule_ref: ..., explanation: ...}}   # 仅 MATCH/PARTIAL 且规则允许时
no_reports_found: false                 # 官方渠道确无审计报告时显式声明
no_reports_note: ...
conclusion: NEW|KNOWN
```

**Gate 规则**(遵循既有哲学:UNKNOWN 阻塞、例外须引用规则):
- `discovery` 非空;`reports` 为空时必须 `no_reports_found: true` + note
- 每份报告:文件存在、sha256 匹配、恰有一条 checks 记录
- `NO_MATCH` 须有关键词与 detail;`NOT_SEARCHABLE` 视为未决 → 阻塞(走 `record blocker`)
- `MATCH`/`PARTIAL` 默认阻塞并提示 `close INELIGIBLE --evidence <重合分析>`;仅当附 `still_eligible {rule_ref, explanation}` 才放行
- `conclusion: KNOWN` 一律阻塞;ledger 合并 `prior_art` 摘要字段(含字段哈希,后续篡改会失效 gate)
